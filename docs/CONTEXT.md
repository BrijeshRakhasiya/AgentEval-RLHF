# AgentEval-RLHF: Project Context & Domain Specification

## 1. Executive Summary & Core Objective
`AgentEval-RLHF` is an enterprise-ready, open-source AI Agent Evaluation & Reinforcement Learning from Human Feedback (RLHF) Data Pipeline Engine. Built to replicate frontier AI data platforms (such as micro1, Scale AI, and Abundant), this system executes multi-step LLM reasoning traces, subjects outputs to dual deterministic and qualitative evaluations, enables human expert interventions, and exports fine-tuning artifacts (`SFT` and `DPO` pairs). 

Our ultimate objective is to evolve from a local evaluation script into a **secure, scalable, and automated AI data flywheel** that serves as the definitive evaluation layer for autonomous AI agents.

## 2. Industry Problem Statement & Business Alignment
Frontier LLM development is shifting from static benchmark testing to dynamic, environment-based evaluation. Current industry bottlenecks include:
- **Brittle Auto-evaluators:** Pure LLM-as-a-Judge systems suffer from self-preference bias, verbosity bias, and non-deterministic logic failures (e.g., brittle regex JSON parsing).
- **Data Curation Overhead:** Bridging raw model failure logs to standardized DPO/SFT training pairs requires fragmented, manual engineering, creating a massive labeling bottleneck.
- **Sandbox Risks:** Executing code generated by LLM agents poses severe execution hazards (resource exhaustion, system escapes) without strictly isolated, zero-trust containerized environments.

`AgentEval-RLHF` addresses these gaps by combining ephemeral sandbox execution, multi-critique structured LLM judging, and a unified Human-in-the-Loop (HITL) curation dashboard powered by an RLAIF (Reinforcement Learning from AI Feedback) data flywheel.

## 3. Scope & System Boundaries

### In-Scope (Current & Near-Term Roadmap)
1. **Agent Trajectory Capture:** Ingests user prompts, system prompts, tool execution logs, and final generated code/text from LLMs.
2. **Zero-Trust Deterministic Evaluation:** Runs Python and C++ code in isolated, ephemeral microVMs/containers (e.g., E2B, Docker + gVisor) with strict timeout, memory constraints, and pre-execution static security analysis (e.g., `bandit`, `cppcheck`).
3. **Structured Qualitative Evaluation (LLM-as-a-Judge):** Configurable, multi-dimensional scoring rubrics (Correctness, Security, Complexity) utilizing native schema enforcement (e.g., `instructor` library) for >99% JSON adherence.
4. **RLAIF Data Flywheel & Smart HITL:** Automated confidence routing that auto-generates and approves high-confidence "Chosen" DPO pairs, reserving the Streamlit dashboard exclusively for human expert review of edge cases and low-confidence trajectories.
5. **Data Exporter & Observability:** Native formatting into Hugging Face / OpenAI compatible `.jsonl` files, coupled with telemetry logging (LangSmith / Arize Phoenix) for drift detection and performance auditing.
6. **Repo-Level Evaluation (v1.1):** Support for cloning git repositories, applying code patches, and running native test suites (SWE-bench style).

### Out-of-Scope (v1.0)
- Distributed GPU model training execution directly inside the web engine (delegated to external frameworks like Axolotl/TRL).
- Direct multi-tenant SaaS authentication and billing (delegated to v2.0 enterprise roadmap).

## 4. Key Performance Indicators (KPIs) & Target Metrics
- **Sandbox Isolation & Security:** 100% prevention of host system escapes or resource exhaustion (fork bombs).
- **Subprocess Execution Latency:** < 2.0s per isolated test execution suite.
- **Judge Scoring Parse Rate:** > 99.5% JSON schema adherence via structured output enforcement (zero regex fallbacks).
- **RLAIF Auto-Approval Rate:** > 80% of passing, high-confidence trajectories automatically synthesized into DPO pairs without human intervention.
- **Data Export Throughput:** Real-time, append-only stream to `.jsonl` with zero memory leaks.

## 5. Strategic Implementation Roadmap (The Top 1% Path)
To achieve frontier-grade status, development will follow this strict, phased Agentic Development Life Cycle (ADLC):

### 🚀 Phase 1: Enterprise-Grade Secure Sandboxing
- **Objective:** Eliminate legacy `subprocess` security risks.
- **Actions:** 
  - Integrate `e2b-code-interpreter` or Docker SDK into `src/sandbox.py`.
  - Implement ephemeral environment spin-up, execution, and guaranteed teardown.
  - Update `ExecutionTrace` Pydantic model to include `security_flags` and `sandbox_type`.
  - Write integration tests verifying malicious code blocking and strict timeout enforcement.

### 🧠 Phase 2: Multi-Dimensional & Structured Evaluation
- **Objective:** Replace brittle parsing with guaranteed structured outputs and add static analysis.
- **Actions:**
  - Integrate `instructor` library for native Pydantic schema enforcement in `src/judge.py`.
  - Create `src/analyzer.py` to run `bandit` (Python) / `cppcheck` (C++) scans *before* dynamic execution.
  - Expand `JudgeResult` to include `security_score`, `complexity_rating`, and `correctness_score`.
  - Update LLM system prompts to explicitly evaluate the static analysis report alongside execution logs.

### 🔄 Phase 3: RLAIF Data Flywheel & Smart Routing
- **Objective:** Automate 80% of DPO pair generation to eliminate human labeling bottlenecks.
- **Actions:**
  - Build `src/router.py` with a `ConfidenceRouter` class.
  - Implement routing logic: If `passed == True` AND `combined_score >= 4.5`, trigger a stronger model (e.g., DeepSeek V4 Pro) to auto-generate the optimized "Chosen" response.
  - Route only medium/low-confidence or failing trajectories to the Streamlit HITL dashboard.
  - Tag all `DPODatasetEntry` exports with `"generation_method": "rlaif_auto"` or `"human_curated"`.

### 📊 Phase 4: Repo-Level Eval, Observability & CLI
- **Objective:** Support real-world agent scenarios and provide enterprise-grade monitoring.
- **Actions:**
  - Develop `agent_eval` CLI (via `typer` or `click`) for rapid terminal-based evaluation (e.g., `agent-eval run --file agent.py --tests test.py --export-dpo`).
  - Implement "Repo-Level" mode in the sandbox to clone repos, apply patches, and run native `pytest` suites.
  - Integrate `src/observability.py` to log all evaluation traces to LangSmith or Arize Phoenix.
  - Update repository `README.md` to highlight Top 1% features: E2B security, RLAIF flywheel, and SWE-bench compatibility.
